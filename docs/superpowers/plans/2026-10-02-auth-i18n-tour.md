# Authentication, bilingual UI and onboarding implementation plan

> **For agentic workers:** Use subagent-driven-development for independent backend and localization tasks, then integrate and review in this worktree. Steps use checkbox syntax for tracking.

**Goal:** Add an authenticated English/Traditional Chinese researcher UI with shared Radix controls and a safe quick-start tour.

**Architecture:** Authentication is isolated from the evidence graph. Translation resources and language preference live in an independent frontend module. A session boundary wraps the app; shared Radix components support login and tour.

**Tech Stack:** Python 3.11+, FastAPI, stdlib scrypt, React 18, Vite, Radix UI, i18next and react-i18next.

**Spec:** `docs/superpowers/specs/2026-10-02-auth-i18n-tour.md`

## Global constraints

Absolute Python imports; no output-token limits; no restricted dataset or secret commits; localhost binding; retain source text and researcher/model prose unchanged; do not change evidence promotion semantics; record deliberate HTTP/CLI auth asymmetry in parity tests. Preserve the presentation branch; work in feat/auth-i18n-tour.

## Task 1 Authentication boundary

Interface: `AuthManager.from_file(path)` loads username/hash. `mount_auth(app, manager)` installs auth routes and middleware. `create_app(..., auth=None)` remains usable for existing programmatic callers.
