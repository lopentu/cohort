# Authentication, bilingual UI and onboarding

Approved by the presenter on 2 October 2026: one researcher account, English and Taiwan Traditional Chinese, replayable onboarding, shared Radix UI components, and a browser UX sweep.

## Boundaries

The login protects the browser application and its research APIs. It does not implement corpus licence governance, multi-user research ownership or ATELIER integration. The evidence log and researcher promotion rules remain unchanged. Bind the server to localhost and use SSH forwarding. No deployment topology changes or public exposure.

## Authentication

A local interactive setup command writes a username and scrypt password hash to an ignored, owner-readable credentials file. Use OWASP's scrypt parameters N=16384, r=8, p=5, a random salt and constant-time comparison. No passwords in command arguments or logs. Normal serve_ui startup requires credentials; explicit local-only opt-out is documented for controlled development.

An independent authentication module owns random server-side sessions, idle and absolute expiry, revocation, bounded login rate limiting, and CSRF verification on state-changing requests. Research routes, OpenAPI and docs require login; only the login shell, static assets and minimal auth endpoints are public. Cookies are HttpOnly and SameSite=Strict; Secure applies when served over HTTPS, with an explicit localhost HTTP setting for SSH forwarding. Login checks origin and JSON content type. Authentication failure returns structured error codes, never database paths or source data. The API client handles session expiry centrally.

## Localization

Use i18next and react-i18next with checked-in English and zh-TW resources. Persist the selected language, set document lang, and format dates/numbers with the active locale. Translate application-owned controls, statuses, help, error chrome and accessibility labels. Preserve researcher input, source texts, opaque IDs, model output and backend diagnostic details. Do not translate by rewriting the DOM or changing graph records.

## Components and tour

Use Radix UI primitives behind shared controls, including button, field, notice, dialog and tabs. Preserve the current design tokens and graph semantics. A tour introduces each available tab with plain descriptions and selectable examples; never issue paid calls or create records. It is dismissible, replayable, responsive and keyboard accessible. Disabled features are omitted. Record completion locally with a versioned key.

## Validation

Security tests cover unauthorized direct access, wrong credentials, retry limits, cookie properties, CSRF, origin rejection, logout and expiry. Localization tests cover saved preference, unsupported locale fallback and both-language key coverage. Browser checks cover real login, both languages, all enabled tabs, the tour, keyboard focus, light/dark mode, small screens and session expiry. Use synthetic source fixtures in screenshots, never restricted source text. Run the full Python and JavaScript suites, frontend build, ruff and ty before committing.
